## Findings

### F-001 — Interfaces state today's board as twelve by twelve; code is 120 by 120

- Severity: BLOCKER
- Location: `wiki/work/0010-restart-on-death/01-plan.md:83`
- Criterion affected: none (shared construction decision; not an AC gap)
- Observation: Interfaces require replacement construction inputs of "width twelve, height twelve". `example/lib/snake_screen.dart:33-34` constructs width 120 and height 120; `example/test/snake_screen_test.dart:24-27` asserts those literals; `wiki/product/classic-snake-example.md:29` documents 120 by 120. Approach prose at `01-plan.md:9` correctly says to match today's screen width and height, so the plan contradicts both the codebase and itself. Related research claims the same false size (`00-research.md:21`, `research/end-state.md:39`) but the implementer-facing shared decision lives in the plan.
- Why it matters: An implementer following the Interfaces line would change the production board size on restart or diverge from "match today's screen construction", inventing user-visible behaviour the contract does not ask for.

### F-002 — Constructor replacement assumes a reassignable controller field without stating today's `late final`

- Severity: IMPORTANT
- Location: `wiki/work/0010-restart-on-death/01-plan.md:82`
- Criterion affected: AC-006
- Observation: The plan decides that the screen owns replacing the ended controller with a newly constructed one. `example/lib/snake_screen.dart:25` declares `late final SnakeController _controller`, which cannot be reassigned as written. The plan never states that this declaration must change (or an equivalent ownership shape) for constructor replacement to compile.
- Why it matters: The chosen mechanism is blocked by the current field binding until that binding is changed; leaving it unstated makes the first compile failure look like an accidental edit rather than a required ownership change.

### F-003 — Screen session-free proof leaves the harness seam undecided

- Severity: IMPORTANT
- Location: `wiki/work/0010-restart-on-death/01-plan.md:15`
- Criterion affected: AC-006, AC-009, AC-011
- Observation: U3/U4 require a screen-level check that death invokes new-run and continues the loop without opening a session, "using whatever injection or harness seam the screen needs" (`01-plan.md:15`, scenario at `01-plan.md:77`). Production `SnakeScreen` only accepts `LoadedRuntime` and wires `runtime.predict` (`example/lib/snake_screen.dart:15-18`, `37-38`). `LoadedRuntime.validationOnly` has no session and `predict` throws `StateError` (`lib/src/loaded_runtime.dart:34-43`, `68-71`), so pumping today's screen cannot drive wall/body death or title restore without a new seam. The plan does not choose that seam's shape (optional predict override, test subclass, factory, or other).
- Why it matters: AC-006, AC-009, and AC-011 depend on that proof path; an open seam choice will be invented during implement and may need another validation round.
